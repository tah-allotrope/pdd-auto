01 / Executive Summary

Executive Summary

The problem. This project drafts Verra carbon-credit Project Design Documents (PDDs). Its calculation engine — the part that produces the tonnes of CO2 a project can claim — was wired into the drafting pipeline last week and immediately began telling the language model that its numbers were authoritative. Nobody had checked whether they were correct.

What we found. They were not. For waste-to-energy projects, the engine computed zero avoided landfill methane — the single largest term, and the entire economic case for the project type. On the Soc Son reference project it produced 2,499,042 tCO2e against the 3,808,082 tCO2e published in that project's own registered VCS document: a 34% shortfall. A second project could not be calculated at all.

What we did. Two of the plan's six phases are complete. The cause was a single line conflating two different fractions of the waste stream: the engine scaled avoided landfill methane by the share of waste sent to anaerobic digestion rather than the share diverted from landfill. A mass-burn incinerator digests nothing and still keeps its entire throughput out of the ground, so the term collapsed to zero by construction. Soc Son now lands at 3,413,977 tCO2e — within 10% of the registered figure, down from 34%.

Why it matters beyond the fix. The more durable change is the test that caught it. The repository had 752 tests, all of which verified that the engine reproduced its own arithmetic. None compared it to a document a validator had actually approved. There is now a regression suite that checks engine output against figures published in real registered PDDs — the first evidence in this codebase that the quantification is defensible rather than merely self-consistent.

Honest status. One project still fails its check and we did not hide it. The remaining gap is understood precisely, is not a calculation error, and is scheduled work rather than an unknown — see Findings.

02 / Background & Objective

Background & Objective

A Project Design Document is the filing that determines whether a carbon project earns credits. Its narrative sections can be drafted by a language model; its numbers cannot be — they must trace back to a published methodology, and a third-party validator will argue with every one of them.

This repository has carried roughly 1,800 lines of methodology code (ACM0022 for waste-to-energy, plus rice, biochar and cookstove engines and seven CDM calculation tools) for months. Until commit 47a4faf it was connected to nothing. That commit wired it into the drafting pipeline so the engine's output is injected into prompts as the authoritative source of quantification.

An audit of that newly-connected engine — the brainstorm that produced this plan — found that connecting it was not the same as making it right. The objective of this push was therefore narrow and specific: establish whether the engine's numbers survive contact with reality, and fix them where they do not, before any further work is layered on top and before a paid real-model production run is commissioned against them.

04 / Assumptions & Constraints

Assumptions & Constraints

Methodology reading (material)

We assume ACM0022's avoided-methane term applies to all waste diverted from landfill, not only the portion routed to anaerobic digestion. This is the change's entire premise. It is supported by the registered documents — the corrected engine moves toward them from every direction — but it is a domain judgement a methodology specialist should confirm.

Tolerance band

Engine output is accepted within ±20% of the registered figure. The project configuration files lack waste-composition splits and site-specific project emissions, so an exact match is not achievable. 20% absorbs that while remaining tight enough that a structurally missing term cannot hide inside it — the pre-fix errors of 34% and 68% both fail it.

Ground-truth extraction

The four reference figures were read out of the registered documents' text and are hard-coded as constants rather than re-parsed at test time, so the tests run without the (large, untracked) corpus present. If a figure was misread, the test is wrong in a way the code cannot detect.

Unverifiable inputs

İnegöl's anaerobic-digestion fraction is not published in its PDD; 0.35 was assumed and labelled as an assumption in the configuration. It affects only the digestion pathway, not the corrected methane term. No cost was incurred in this push — all work was offline and deterministic.

05 / Methodology

Methodology

The push followed a strict test-first discipline, which mattered more than usual here because the failure being chased was a silent one — code that ran cleanly and produced confident, wrong numbers.

  1. Write the check before the fix. Both phases began by writing tests that encoded the desired behaviour and running them to confirm they failed. The output-normalizer bug and all four engine discrepancies were observed as red tests before any source file was edited.
  2. Use an external oracle, not internal consistency. The decisive move was testing against published figures from documents that third-party validators had already approved. A codebase can be perfectly self-consistent and uniformly wrong; only an outside reference distinguishes the two.
  3. Diagnose before adjusting. When a check still failed after the fix, we measured the cause rather than relaxing the threshold. That measurement produced a precise, scheduled explanation instead of a passing test that meant nothing.
  4. Prove the mechanism, not just the outcome. Tests assert that the two waste fractions are genuinely independent — changing the digestion fraction must leave avoided methane untouched, while changing the diversion fraction must scale it proportionally. This prevents a future refactor from silently re-coupling them.

06 / Phase-by-Phase Analysis

Phase-by-Phase Analysis

PHASE-01 — Pre-flight safety

Four independent hazards, all of which would have corrupted a paid production run:

  • Silent content deletion. The routine that strips conversational filler from model output scanned the whole document for closing phrases. "Note: I've applied the national grid emission factor…" is how a PDD discloses an assumption, not chatter — so a two-section test body lost 135 of 209 characters, including an entire subsection. Now a closing phrase is only removed when it forms an unbroken block at the very end.
  • An uncomputable flagship project. İnegöl returned no calculation at all for want of a grid emission factor. The value did not need inventing: its own registered PDD publishes the components (0.5 × 0.3541 + 0.5 × 0.7279 = 0.5410 tCO2/MWh).
  • Grounding on 3 documents instead of 17. Retrieval silently fell back to a 3-document demo index whenever the production index was absent — which it was. Built the real index (233 → 1,015 indexed rows) and made the fallback log loudly.
  • Unrecorded provenance. Run scorecards now record which index and which methodology backed the numbers.

PHASE-02 — Engine correctness

The oracle test was written first and failed on four of five assertions, reproducing the audit's predictions exactly: −34.4% on Soc Son, −68.4% on İnegöl, and avoided methane of precisely zero.

The fix introduces swds_diversion_fraction (defaulting to the full throughput) and scales avoided landfill methane by it, leaving the digestion fraction to govern only biogas and digestion-related emissions. It is a small change with a large effect because it restores a term that had been multiplied to nothing.

Notably, no existing test needed its expected value rewritten — none had been pinned to the zero-methane result, which suggests the defect predated any deliberate calibration rather than having been baked in.

The one that did not pass

İnegöl improved from −68.4% to −51.4% but still failed. Rather than widen the threshold, we measured it: the registered 104,285 tCO2e/yr is a seven-year average, while the engine's headline figure describes year one of a decay curve — structurally the smallest year. Year three (107,226) already brackets the published average almost exactly.

The two affected assertions are marked as known-failing with the measured numbers recorded in the code. Summing a proper year-by-year schedule moves this from −51% to +22%, which is PHASE-03's scheduled work.

What the sequence bought

PHASE-01 was not merely housekeeping. Its grid-emission-factor work is what made İnegöl's independent check possible at all, and that check is what proved the remaining gap was a reporting-period artefact rather than a second calculation error. Had the phases run in the other order, the İnegöl signal would have been unavailable and the year-one diagnosis far harder to reach.

07 / Findings & Recommendation

Findings & Recommendation

Finding 1 — The engine was the outlier, not the project data

This inverts the intuitive reading. The human-authored Soc Son configuration declares 3,808,532 tCO2e against the registered document's 3,808,082 — a match to within 0.01%. The engine's 2,499,042 was the number out of line. Anyone reconciling the two by editing the configuration downward would have destroyed correct data to satisfy broken code.

Finding 2 — A missing term, not an imprecise one

Avoided landfill methane was not approximately wrong; it was exactly zero on every waste-to-energy project, because it was multiplied by a fraction that is legitimately zero for incineration plants. Errors of this shape do not announce themselves — the engine ran cleanly and reported confident totals throughout.

Finding 3 — Self-consistency had been mistaken for correctness

752 tests passed against an engine understating its flagship methodology by a third. Every one verified internal arithmetic. The single most valuable artefact from this push is not the fix but the external oracle that makes the class of error visible at all.

Tradeoffs and rejected options

  • Rejected: widening the tolerance to 40% so İnegöl would pass. This would have produced a green suite that certified nothing. The known-failing marker preserves the signal and carries the measured numbers forward.
  • Rejected: the plan's own "last 3 lines" heuristic for the text-truncation fix. On testing, the offending line was within the last three lines of the fixture. The implemented rule — a closing phrase must form an unbroken block at the end — is simpler and correct for the right reason. This is a deliberate deviation from the written plan.
  • Accepted risk: the diversion fraction defaults to 100% of throughput. For projects that divert only part of their intake this overstates the baseline; no current configuration expresses partial diversion, and the field exists to carry it when one does.

Recommendation

Proceed to PHASE-03. The year-by-year schedule is now the highest-value remaining item for two independent reasons: it is required by the Verra template regardless, and it is the specific, measured thing standing between İnegöl and a passing independent check. Do not commission the paid production run (PHASE-06) until the calculation reaches the exported document in PHASE-04 — until then the numbers are computed but never shown to the human who must defend them.

08 / Implementation Path

Implementation Path

Next — PHASE-03: year-by-year schedule

Emit a per-year emission-reduction series rather than one number multiplied by the period length, and populate the four monitoring parameters the engine already knows but discards. Expected to move İnegöl from −51% to roughly +22% and to flip the two known-failing assertions. Dependency: none beyond what has landed. Offline; no cost.

Then — PHASE-04: carry the result into the document

The calculation is currently discarded before export: it is not saved with the run, so the export step — which runs later and separately — cannot recover it. Persist it and render an audit appendix. This is what a validator actually reads. Offline; no cost.

Then — PHASE-05: tables and precedence

Turn the calculation into the first producer of the eleven Verra-shaped tables that exist in the exporter but have never been populated, and formalise which source wins when the engine and the project file disagree. Offline; no cost.

Last — PHASE-06: the paid production run

Approximately US$12–16 and about an hour, against a real language model. Gate it on PHASE-04 at minimum. Set the cost ceiling explicitly; run one project, read the scorecard, then decide on the second.

09 / Risks / Open Questions

Risks / Open Questions

Open: is the methodology reading right?

The fix rests on a domain judgement about what ACM0022's avoided-methane term covers. The evidence is strong — the corrected engine moves toward two independent registered documents — but a methodology specialist should confirm it before the numbers are shown to a client. This is the single highest-value review this push could receive.

Open: project emissions are still zero

Every waste-to-energy configuration reports zero project emissions and zero leakage, because auxiliary fuel, grid draw and ash handling are not carried in the input schema. A filing asserting an incinerator has no emissions of its own will not survive validation. Not addressed here.

Risk: the tolerance is a judgement, not a standard

±20% was chosen deliberately and is documented in the test file, but it is our number, not Verra's. It is loose enough that a real but moderate error could pass. Tighten it as the input coverage improves.

Risk: two of six phases complete

The engine is now more accurate, but its output still does not reach the exported document, and the four remaining phases are unstarted. Nothing in this push changes what a client would receive today. Treat these results as an internal correctness milestone, not a deliverable.
