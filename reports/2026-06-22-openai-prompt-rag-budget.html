3. Math / Algorithm Used

Token Budget Tracking

Budget Utilization
utilization = (Σ input_tokens + Σ output_tokens) / max_tokens
Cost Estimation (GPT-4o)
cost_usd = (input_tokens / 1M) × $2.50 + (output_tokens / 1M) × $10.00
  • Warning threshold: 80% utilization → structlog warning emitted (once)
  • Hard stop: 100% utilization → BudgetExhaustedError raised, section gets UNSUPPORTED placeholder
  • Default budget: 500,000 tokens per run (~$1.25 at GPT-4o input pricing for a full 20-section PDD)

Authority Order (Prompt Discipline)

When sources conflict, the prompt enforces this strict priority:

  1. Input YAML — ProjectInput (highest)
  2. Evidence — Retrieved corpus + methodology
  3. VCS Template — Template v4.4 structure
  4. Methodology — ACM0022/ACM0003 rules
  5. Examples — Corpus PDD patterns
  6. Domain Logic — General WTE knowledge (lowest)

6. Limitations / Second-Best Alternative

LimitationMitigation / Alternative
OpenAI provider requires an API key and network access NoopProvider and DemoProvider remain available for offline/zero-cost usage. The Ollama stub is preserved for local model support.
PDF export depends on LibreOffice installation is_libreoffice_available() check + graceful PDFExportError. DOCX export remains the primary path.
Token budget pricing is hardcoded for GPT-4o family Pricing dict is extensible. Unknown models fall back to GPT-4o pricing for estimation.
Retry logic uses exponential backoff (2/4/8s) — may be slow under sustained rate limits 3 retries max, then surfaces the error. Could be extended with configurable retry policies.
Anti-hallucination markers depend on GPT-4 compliance with instructions Confidence assessment post-processes output to detect and flag markers. Human review gates enforce quality.
