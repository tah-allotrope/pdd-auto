PHASE 3 COMPLETE — 9/9 TASKS PHASE 4 NEXT: Registry API + Monitoring

Phase 3 adds two capabilities the pipeline previously lacked: (1) LLM-based extraction of structured ProjectInput from arbitrary DOCX/PDF/text documents using a dedicated extraction prompt with [MISSING] handling, and (2) rule-based methodology screening that scores project descriptions against 12 Verra VCS and CDM methodologies using a 5-factor weighted algorithm, returning ranked SuggestedMethodology suggestions with confidence scores. These unlock fast onboarding of new projects beyond the manual spreadsheet workflow. Three new CLI commands (extract, screen, draft --from-doc) expose the full document-to-PDD pipeline.

3. Math / Algorithm Used

Methodology Screening — 5-Factor Weighted Scoring

Confidence Score
confidence = 0.25 × tech + 0.15 × waste + 0.15 × category + 0.25 × conditions + 0.20 × mention
FactorWeightScoring RuleRange
Technology Match0.25 1.0 if technology_type is in methodology's applicable_technology_types; else 0.0 [0, 1]
Waste Match0.15 Fraction of project waste types found in methodology's waste_types [0, 1]
Category Match0.15 Keyword overlap between description and methodology category, capped at 1.0 [0, 1]
Applicability Conditions0.25 Fraction of conditions whose key words (length > 4) appear in description at ≥ 30% match rate [0, 1]
Methodology Mentioned0.20 1.0 if ID (e.g. "acm0022") found in text; 0.3 if ≥ 60% of name words (> 5 chars) match; else 0.0 [0, 1]

6. Limitations / Second-Best Alternative

LimitationMitigation / Alternative
Methodology screening is rule-based, not LLM-based Deterministic, fast, and testable. An LLM-based screener could improve recall for novel methodologies but would need additional API calls and non-deterministic testing. The current 5-factor approach correctly ranks ACM0022 first for all WTE test cases.
Extraction quality depends on input document format and completeness [MISSING] markers are recursively cleaned and replaced with schema defaults. ExtractionProvenance tracks exactly which fields were extracted, defaulted, or missing.
Methodology data is static JSON — may become stale Both JSON files include _meta.last_updated timestamps. The screening module logs its data version. Files are easily replaceable; Phase 5 (Registry API) will automate refresh.
Document text extraction limited to DOCX and PDF formats _read_text_from_file dispatches by suffix and falls back to UTF-8/latin-1 for unknown formats. Scanned-image PDFs without OCR layer would produce empty text.
Name-based methodology matching can produce false positives Tightened after AM0025 calibration: name words must be > 5 chars, ≥ 60% word match required, and name match score reduced from 0.5 to 0.3. ID match (1.0) remains the strongest signal.

8. Open Questions / Next Phase Seeds

  • Phase 4: Registry API — Verra next-gen registry integration for project metadata, VCU tracking, and automated methodology list refresh
  • Phase 5: Monitoring & Quality Gates — Extraction quality scoring, automated provenance validation, confidence calibration across projects
